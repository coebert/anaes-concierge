# Project rules

- Page every multi-row database read through `src/lib/paged-fetch-core.ts` (directly or via its wrappers) with a stable order — the API caps responses at 1000 rows and truncation must surface as an error, never as a short list.
- All leave-day counting, leave-year windows and proration go through `src/features/leave/leave-count.ts` — screens previously disagreed on the same dates.
- The TCS module is an estimated screen: never emit a definitive "compliant" result from inferred shift times.
- A failed fetch must render an error with Retry (`QueryErrorNotice`), never an empty or zero state; editors that validate against loaded data stay blocked until it loads.
- Dependency scanning runs `bun audit` on the committed `bun.lock`, validates lock/report schemas and fails closed; there is no alternate lockfile.
- Database schema/RLS checks are proven in the disposable harnesses `tests/db-harness/run.sh` (SQL cases) and `tests/db-harness/postgrest.sh` (real PostgREST) for migrations 0000–0006, and `tests/db-harness/definer/run.sh` (non-superuser postgres owner in service_role, SQL + real PostgREST) for 0007+ — the earlier fixture's superuser owner cannot reproduce definer-identity bugs.
- SECURITY DEFINER bodies never use current_user/pg_has_role(current_user, …) to identify the caller (it is the owner); use `_request_is_service_role()` / `_request_is_authenticated_user()` / `_request_is_active_admin()` / `_request_is_verified_scheduler()` from migration 0007.
- The audit SQL role reads only columns in the reviewed `audit_ro.column_allowlist`; never switch back to a computed denylist.
- Auth identity changes are applied synchronously (reset + loading gate + cache purge) before the new session is published; only network loads are deferred.
- Non-registry dependencies must be listed with exact resolution+integrity in `scripts/supply-chain-unscanned.json` or the scanner fails.
- Wellbeing scores below the coverage gate (`MIN_ASSESSABLE_SESSIONS`) are `unknown`, never a good score; admin retention inputs go through `src/features/wellbeing/admin-inputs.ts` with an explicit as-of date — absent or future data must not read as good wellbeing.
- The retention "attrition" rubric is an unvalidated signal score shown as x/100 with the band picked from the displayed integer; never present it as a prediction or probability.
- Every handler that uses service-role data or privileged tools first passes the shared active-membership check (`src/lib/app-membership.ts` / `requireActiveMember`), failing closed — a valid token alone is not membership.
- Assistant streams hold a durable per-user lease (`chat_stream_leases` RPCs) released on finish/error/abort with TTL recovery; refuse the request if the lease store is unavailable.
- Theatre pressure forecast tags come only from explicit whole-word labels in `src/features/audit/procedure-tags.ts` (never surgeon, theatre name or specialty); raw label text/IDs are stripped before caching or display, and missing labels read as unknown.
- Original CLWRota list titles/notes live only on service-role-only `theatre_session_source_labels` (written by `src/features/clwrota/source-labels.ts`); browsers get derived signals via `get_theatre_session_label_signals` — the raw text is potentially sensitive. The forecast still falls back to legacy fields for sessions with no source-label row.
- Week rota status comes only from the feed's `assignments.rota_status`, recorded per observed week by `src/features/clwrota/week-status.ts`; unobserved weeks are unknown, observation times are not publication times, and `assignments.state` 'actual' is not delivered work.
- Anaesthetic cover rules (solo-capable grades, SPA contingency, risk thresholds, worst-half order, shared wording) live only in `src/features/audit/cover-rules.ts` — screens previously described different grade sets.
- Cover-config reads (e.g. `duty_type_pool_rules`) throw on error; built-in defaults apply only to a successful empty read, so a failure shows Retry instead of numbers.
- Per-week rota import coverage/freshness comes only from per-run windows in service-only `clwrota_sync_windows` (written by `src/features/clwrota/sync-windows.ts`, read via `get_rota_sync_week_coverage`); it is separate from publication status, untracked weeks are unknown, and partial/failed/empty runs never count as coverage.
- CLWRota day-off detection lives only in `isNonWorkingRotaLabel` (`src/lib/clwrota-labels.ts`): "off site" is a location phrase and is the only thing neutralised; any independent off/leave/rest marker on the row still drops it — the bare "off" inside "Off site" once dropped real Laser lists.
- CLWRota rows without a source id share the person|date|half fallback key: the non-working clean-up deletes only keys never carried by any working-classified feed row (`src/features/clwrota/non-working-cleanup.ts`; evidence is recorded before later row skips), and two working rows on one fallback key resolve by the duty priority in `assignment-dedupe.ts`, not feed order — working rows were deleted after saving and the stored duty flipped with row order.
- Blank-list reconciliation (lists with nobody linked vs CLWRota rows placed on no list) lives in `src/features/clwrota/session-reconciliation.ts`; an unplaced theatre row on the same half is only a candidate, and a list is "nobody in the feed" only when that week's import is complete and current — the feed lists people, not sessions, so it can't tell cancelled from uncovered.
